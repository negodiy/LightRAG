# Сравнение Graphiti и LightRAG

## 📊 Общее сравнение

| Аспект | Graphiti | LightRAG |
|--------|----------|----------|
| **Основное назначение** | Временные графы знаний для AI-агентов | RAG с графом знаний для документов |
| **Фокус** | Динамические данные, реальное время | Статические документы, индексация |
| **Временная модель** | Битемпоральная (время события + время индексации) | Базовая временная метка |
| **Обновления** | Инкрементальные, без пересборки | Требует переиндексации при изменениях |
| **Звёзды GitHub** | ~20,359 | Активно развивается |
| **Лицензия** | Apache 2.0 | Открытая |
| **Язык** | Python | Python |

---

## 🎯 Архитектурные различия

### Graphiti

**Концепция:**
- **Эпизоды (Episodes)**: Основная единица данных - временные эпизоды взаимодействий
- **Битемпоральная модель**: Отслеживает время события (valid_time) и время индексации (transaction_time)
- **Автономное построение графа**: Граф строится автоматически из эпизодов
- **Гибридный поиск**: Семантические эмбеддинги + BM25 + обход графа

**Ключевые особенности:**
- ✅ Реальное время: данные интегрируются немедленно
- ✅ Исторические запросы: точные запросы на момент времени
- ✅ Обработка противоречий: временная инвалидация рёбер
- ✅ Кастомные сущности: Pydantic модели для определения типов

### LightRAG

**Концепция:**
- **Документы**: Основная единица данных - текстовые документы
- **Извлечение сущностей**: LLM извлекает сущности и отношения из текста
- **Многоуровневая индексация**: Chunks → Entities → Relations → Summaries
- **Гибридный поиск**: Векторный поиск + графовый поиск + reranking

**Ключевые особенности:**
- ✅ Множественные режимы запросов: local, global, hybrid, mix, naive
- ✅ Гибкая архитектура хранения: 4 типа storage (KV, Vector, Graph, DocStatus)
- ✅ Поддержка множества БД: Neo4j, PostgreSQL, MongoDB, Redis, Milvus, Qdrant и др.
- ✅ Web UI и API сервер

## 🔄 Обработка данных

### Graphiti

```python
# Эпизод - основная единица данных
episode = {
    "user_id": "user123",
    "content": "Kendra loves Adidas shoes",
    "timestamp": "2024-01-15T10:30:00Z"
}

# Инкрементальное добавление
graphiti.add_episode(episode)
# Граф обновляется немедленно, без пересборки
```

**Процесс:**
1. Эпизод поступает в систему
2. LLM извлекает сущности и отношения
3. Данные интегрируются в граф с временными метками
4. Векторные индексы обновляются инкрементально

### LightRAG

```python
# Документ - основная единица данных
rag.insert("Your text document here")

# Или батч-вставка
rag.insert(["Doc1", "Doc2", "Doc3"])
```

**Процесс:**
1. Документ разбивается на chunks
2. LLM извлекает сущности и отношения из каждого chunk
3. Сущности и отношения агрегируются и суммируются
4. Данные индексируются в граф и векторную БД

## 🔍 Поиск и запросы

### Graphiti

**Типы запросов:**
- Семантический поиск (embeddings)
- Ключевые слова (BM25)
- Обход графа (graph traversal)
- Временные запросы (point-in-time queries)

**Пример:**
```python
# Запрос с временным контекстом
results = graphiti.query(
    "What did Kendra like?",
    valid_time="2024-01-15T10:30:00Z"  # Запрос на конкретный момент времени
)
```

**Особенности:**
- Низкая задержка (sub-200ms в продакшене)
- Точные исторические запросы
- Автоматическая обработка изменений во времени

### LightRAG

**Режимы запросов:**
- `naive`: Базовый векторный поиск
- `local`: Фокус на локальном контексте (сущности)
- `global`: Глобальное знание (отношения)
- `hybrid`: Комбинация local + global
- `mix`: Граф + векторный поиск

**Пример:**
```python
# Разные режимы запросов
result_naive = rag.query("What are the themes?", param=QueryParam(mode="naive"))
result_local = rag.query("What are the themes?", param=QueryParam(mode="local"))
result_global = rag.query("What are the themes?", param=QueryParam(mode="global"))
result_hybrid = rag.query("What are the themes?", param=QueryParam(mode="hybrid"))
result_mix = rag.query("What are the themes?", param=QueryParam(mode="mix"))
```

**Особенности:**
- Гибкая настройка через QueryParam
- Поддержка reranking
- Управление токенами (max_entity_tokens, max_relation_tokens)

## 💾 Хранение данных

### Graphiti

**Поддерживаемые БД:**
- Neo4j 5.26
- FalkorDB 1.1.2
- Kuzu 0.11.2
- Amazon Neptune (Database Cluster или Analytics Graph)
- Amazon OpenSearch Serverless (для полнотекстового поиска)

**Архитектура:**
- Граф: Сущности и отношения с временными метками
- Векторная БД: Эмбеддинги для семантического поиска
- Полнотекстовый поиск: BM25 индексы

### LightRAG

**Поддерживаемые БД:**

**KV Storage:**
- JsonKVStorage (по умолчанию)
- PGKVStorage (PostgreSQL)
- RedisKVStorage
- MongoKVStorage

**Vector Storage:**
- NanoVectorDBStorage (по умолчанию)
- PGVectorStorage
- MilvusVectorDBStorage
- FaissVectorDBStorage
- QdrantVectorDBStorage
- ChromaVectorDBStorage
- MongoVectorDBStorage

**Graph Storage:**
- NetworkXStorage (по умолчанию)
- Neo4JStorage
- PGGraphStorage (PostgreSQL + AGE)
- MemgraphStorage

**Doc Status Storage:**
- JsonDocStatusStorage (по умолчанию)
- PGDocStatusStorage
- MongoDocStatusStorage

**Архитектура:**
- 4 независимых типа storage
- Гибкая конфигурация для каждого типа
- Поддержка workspace для изоляции данных

## 🤖 Требования к LLM

### Graphiti

**Требования:**
- Поддержка Structured Output (обязательно!)
- Рекомендуется: OpenAI, Gemini
- Может работать с Anthropic, Groq
- ⚠️ Проблемы с маленькими моделями (неправильные схемы)

**Использование:**
- Извлечение сущностей и отношений из эпизодов
- Генерация эмбеддингов (через embedding API)

### LightRAG

**Требования:**
- Минимум 32B параметров (рекомендуется)
- Контекст минимум 32KB (рекомендуется 64KB)
- Не рекомендуется использовать reasoning модели на этапе индексации
- Поддержка множества провайдеров: OpenAI, Hugging Face, Ollama, Azure, Anthropic, Gemini и др.

**Использование:**
- Извлечение сущностей и отношений
- Суммаризация сущностей и отношений
- Генерация ответов на запросы

## 📈 Производительность

### Graphiti

**Сильные стороны:**
- ✅ Инкрементальные обновления (без пересборки)
- ✅ Низкая задержка запросов (sub-200ms в продакшене)
- ✅ Эффективная параллельная обработка
- ✅ Масштабируемость для больших датасетов

**Слабые стороны:**
- ⚠️ Требует Structured Output от LLM
- ⚠️ Может быть проблематично с маленькими моделями

### LightRAG

**Сильные стороны:**
- ✅ Гибкая архитектура хранения
- ✅ Множественные режимы запросов
- ✅ Поддержка reranking для улучшения качества
- ✅ Кэширование LLM ответов

**Слабые стороны:**
- ⚠️ Требует переиндексации при изменениях документов
- ⚠️ Высокие требования к LLM (32B+ параметров)

## 🎨 Использование

### Graphiti - Идеально для:

1. **AI-агенты с памятью**
   - Отслеживание взаимодействий пользователей
   - Сохранение контекста разговоров
   - Динамические знания о пользователях

2. **Реальное время**
   - Часто обновляемые данные
   - Интерактивные приложения
   - Системы с постоянным потоком данных

3. **Исторические запросы**
   - "Что знал пользователь в момент X?"
   - Аудит и отслеживание изменений
   - Временной анализ данных

4. **Динамические отношения**
   - Отношения, которые меняются со временем
   - Обработка противоречий
   - Эволюция знаний

### LightRAG - Идеально для:

1. **RAG для документов**
   - Индексация корпоративных документов
   - Поиск по технической документации
   - Анализ больших текстовых корпусов

2. **Статические знания**
   - Базы знаний, которые редко меняются
   - Документация
   - Научные статьи

3. **Многоуровневый поиск**
   - Нужны разные режимы запросов
   - Комбинация локального и глобального контекста
   - Гибкая настройка поиска

4. **Исследования и анализ**
   - Извлечение знаний из документов
   - Построение графов знаний
   - Анализ связей между концепциями

## 📝 Примеры кода

### Graphiti

```python
from graphiti_core import Graphiti

# Инициализация
graphiti = Graphiti(
    llm=llm_client,
    embedding=embedding_client,
    database=neo4j_client
)

# Добавление эпизода
episode = {
    "user_id": "user123",
    "content": "I love Python programming",
    "timestamp": "2024-01-15T10:30:00Z"
}
graphiti.add_episode(episode)

# Запрос с временным контекстом
result = graphiti.query(
    "What does the user like?",
    valid_time="2024-01-15T10:30:00Z"
)
```

### LightRAG

```python
from lightrag import LightRAG, QueryParam
from lightrag.llm.openai import gpt_4o_mini_complete, openai_embed

# Инициализация
rag = LightRAG(
    working_dir="./rag_storage",
    llm_model_func=gpt_4o_mini_complete,
    embedding_func=openai_embed
)

await rag.initialize_storages()
await initialize_pipeline_status()

# Вставка документа
await rag.ainsert("Your text document here")

# Запрос
result = await rag.aquery(
    "What are the main themes?",
    param=QueryParam(mode="hybrid")
)
```

## 🎯 Выводы и рекомендации

### Выберите Graphiti, если:

✅ Вам нужны **временные графы знаний**  
✅ Данные **часто меняются** и требуют инкрементальных обновлений  
✅ Нужны **точные исторические запросы**  
✅ Работаете с **AI-агентами** и нужна память  
✅ Данные приходят в виде **эпизодов взаимодействий**  
✅ Нужна **обработка противоречий** во времени  

### Выберите LightRAG, если:

✅ Работаете со **статическими документами**  
✅ Нужна **гибкая архитектура хранения**  
✅ Хотите **множественные режимы запросов**  
✅ Нужна **мультимодальная обработка** (через RAG-Anything)  
✅ Предпочитаете **больше контроля** над процессом индексации  
✅ Нужен **Web UI** и API сервер
